# KalMargin

Статический калькулятор маржинальности. Продолжение существующего PR [#2](https://github.com/Vutovk31/KalMargin/pull/2); состояние выпуска — **кандидат, выпуск заблокирован**. См. [инженерный отчёт](docs/PRODUCTION_STABILIZATION.md).

Для разработки: Node.js 24, npm, Python 3. Для независимой проверки частной реальной выгрузки дополнительно openpyxl 3.1.5 (`python3 -m pip install openpyxl==3.1.5`).

```sh
npm ci
npm run lint
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
npm start
```

На машине с установленным Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`. E2E сами запускают собранный `dist/` на порту 8765; занятый порт — ошибка, чужой сервер не переиспользуется. `npm start` обслуживает исходники на порту 8000. Для развёртывания нужен весь `dist/`, а не один index.html; модульный Worker требует HTTP(S), не file://. В production используйте HTTPS и защитные HTTP-заголовки. Сборка ничего не публикует.

Частную реальную XLSX-выгрузку проверяют отдельно:

```sh
KALMARGIN_REAL_SAMPLE=/absolute/path/to/private-sample.xlsx npm run test:e2e
```

Без этой переменной три частных acceptance-теста явно пропускаются. Публичная CI выполняет синтетические тесты, а не приёмку двух реальных файлов. Частные файлы, трассы и отчёты с коммерческими суммами не коммитить и не загружать в публичные CI-артефакты. В репозитории только явно синтетические XLS/XLSX-фикстуры; `npm run fixtures` создаёт их заново.

Правила: целевая маржинальность по умолчанию **15%**, после сброса также 15%. Пользовательское значение сохраняется при выборе файла. Расчёт использует точные десятичные значения с максимум 6 знаками после запятой; лишняя точность отклоняется, не округляется. Поддерживаются запятая и пробелы-разделители. Цены/закупка ≤ 10¹², количество ≤ 10⁶; итоговые цены — числовые целые рубли ≥ 1 и ≤ floor(исходной цены). Цена ниже рубля блокирует весь рабочий экспорт. Закупка не округляется. Суммы и прибыль считаются точно с максимум 12 десятичными знаками и сохраняются в сводной XLSX как точные десятичные **текстовые** значения; конечная маржа отображается приблизительно (до 4 знаков), решение о достижимости цели принимает точное ядро. Уже утраченную Excel/IEEE-754 точность исходного числа восстановить невозможно.

Импорт: XLS/XLSX ≤ 5 МБ, ≤ 20 листов, ≤ 100 колонок и ≤ 10 000 строк данных; заголовок в первых 25 абсолютных строках. Выбор листа явный, если подходящих листов несколько. Формулы в обязательных данных/заголовках отклоняются даже при наличии кешированного значения; внешние ссылки не вычисляются. Пустая закупка не равна нулю. Дубли SKU предупреждают, не объединяются. Итоговые строки с кодом «Итого/Всего/Total» и пустым количеством исключаются с предупреждением. Непустые строки без кода блокируют экспорт. Числовой SKU с Excel-форматом `00000` сохраняет ведущие нули; утерянные в источнике нули восстановить нельзя.

Отклонения и ошибки можно искать по номеру/коду/причине. Результат ищется по SKU и фильтруется по недостижимой цели. Таблица показывает до 500 найденных позиций, экспорт — весь проверенный расчёт. Недостижимая цель, дубли и исключённые итоги требуют отдельного подтверждения каждого нового расчёта перед XLSX/CSV/копированием. Изменение файла, цели или листа отменяет предыдущую обработку и аннулирует результат.

Диагностика JSON по умолчанию содержит версию/правила/время, количества, номера строк и коды ошибок без SKU, сумм и имени файла. Коммерческие данные и имя файла включаются отдельными флажками. Диагностика не заменяет рабочий экспорт. В CSV/TSV опасные префиксы SKU нейтрализуются апострофом, табуляция и переводы строк заменяются пробелами; в XLSX SKU остаётся строковой ячейкой без формулы. Это защитное преобразование следует учитывать при обратном импорте SKU из CSV/буфера.

Известные риски и обязательное обновление локального Excel-парсера: [vendor/README.md](vendor/README.md). Не вливать в main до выполнения оставшихся критериев.
