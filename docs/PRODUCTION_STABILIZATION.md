## Остаточные риски и критерии выпуска

1. **Блокер:** локальная SheetJS 0.18.5 уязвима (CVE-2023-30533, CVE-2024-22363). Официальный `cdn.sheetjs.com` недоступен через текущую сетевую политику. Требуется применение сохранённого сетевого разрешения, получение и проверка фиксированной официальной версии, обновление всех ссылок/лицензии/checksum и повтор полного набора проверок. Worker/лимиты не устраняют CVE и не задают жёсткий лимит памяти.
2. **Блокер приёмки:** подтверждена **одна из двух** требуемых реальных выгрузок. Нужна вторая независимая выгрузка и предметная сверка менеджером; разные цели на одном файле не считаются разными выгрузками. Автоматический независимый oracle не выдаётся за завершённую ручную приёмку.
3. **Контроль выпуска:** зелёный GitHub Actions для кода подтверждён на `773de98` ссылками выше. Изменения после этого коммита — только актуализация документации; перед слиянием всё равно проверить обязательные checks на окончательном HEAD PR. GitHub API сейчас отвечает Forbidden, однако страницы Actions доступны и подтверждают описанный выше сбой E2E; добавление `api.github.com` сохранено в черновике среды. Наличие workflow не доказывает его удалённый запуск. Для main должны быть включены обязательные проверки/ревью через настройки GitHub; сами workflow не препятствуют ручному обходу владельцем.
4. Проверен Chromium desktop; WebKit/Firefox, Excel desktop/LibreOffice, экранные читалки и реальные маломощные мобильные устройства не проверены. Поддержка Clipboard API требует HTTPS/разрешения браузера; отказ показывается как ошибка, ложного сообщения об успехе нет.
5. Заявленные числовые пределы и точность — явная политика ввода, не произвольное округление закупки. Excel сам хранит числа с ограниченной точностью; уже потерянные разряды не восстанавливаются. Сводные значения XLSX — текст для сохранения точности; потребителям, которым нужны вычисляемые числовые ячейки, потребуется отдельно согласованное правило точности.
6. Worker защищает отзывчивость интерфейса, но не является границей памяти/полноценной песочницей для враждебных архивов. До обновления зависимости не использовать кандидат с недоверенными файлами. Для production настроить HTTPS, `frame-ancestors`/другие HTTP-заголовки и политику кеширования всех файлов одной версии, исключающую смешивание старого и нового ядра.

План внедрения после снятия блокеров: повторить `npm ci`, lint, unit/property, build, Chromium E2E и независимую проверку двух приватных выгрузок; подтвердить CI/ревью; зафиксировать принятый SHA и сохранить предыдущий статический артефакт; только после этого сливать PR и развёртывать **весь** dist. Откат — восстановление предыдущего артефакта целиком или revert merge-коммита через отдельный PR; изменений БД и миграций нет. Текущая работа не сливает и не публикует приложение.
